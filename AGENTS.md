# Agent instructions

Self-hosted Node service that emails each employee their own NI-locked payslip PDF, in Gmail-safe batches. Express API, SQLite, a worker thread for payslip preparation, `qpdf` for encryption. Docs index: [docs/README.md](docs/README.md).

## Commands

```bash
npm ci                    # install (Node 22; better-sqlite3 compiles natively)
npm test                  # node --test; needs qpdf on PATH for the payslip tests
npm start                 # run the app on PORT (default 3000)
make check                # the gate: npm test, tools/gen_diagram.py --check, shellcheck scripts/deploy.sh
make diagram              # redraw docs/assets/*.svg after changing tools/gen_diagram.py
docker compose up -d --build   # the container
```

Run `make check` before and after every change; CI runs the same checks.

## Layout

- `server.js`: Express app and routes
- `src/`: campaigns, db (SQLite schema and migrations), mailer, payslip preparation and matching, settings, worker
- `public/`: the web UI (plain HTML and JS, no build step)
- `tests/`: `node --test` suite
- `scripts/deploy.sh`: builds and pushes the image and rolls the AWS instance
- `terraform/`: AWS deployment; `config/`: sample recipients CSV
- `tools/`: diagram, screenshot and brand generators; `docs/`: guides

## Conventions

- Commits are conventional (`fix:`, `feat:`, `docs:`, `refactor:`, `ci:`, `chore:`) and authored by the repo owner. No co-author trailers, session ids or "generated by" lines in commits, PRs, issues or comments.
- Documentation must be true of the code: verify every command, flag and number, and keep no hand-typed counts that can drift.
- Never force-push `main`. Never commit secrets, keys, tokens, IP addresses, private hostnames, payslips, real recipient data or personal e-mail. The one public contact address is the one already in SECURITY.md.
- Directories `lowercase-kebab`, JS modules `kebab-case.js`, shell scripts `kebab-case.sh`, docs `docs/lowercase-kebab.md`.
- Diagrams are drawn by `tools/gen_diagram.py`; edit the generator, not the SVGs.
- `.env.example` lists every variable the code reads; keep it in step with `docker-compose.yml`, `docs/configuration.md` and `terraform/`.
- Every file the container needs must be in the Dockerfile's `COPY` set (`.dockerignore` excludes `tests`, `scripts`, `terraform`); check it when adding runtime files.

## Do not change (runtime identifiers)

Environment variable names in `.env.example`; the settings table columns and migrations in `src/db.js`; the `/api/*` routes the web UI calls; the container name `payroll-mail-service`, the image repository name and the `mail-data` volume; `DATA_DIR=/data`.
